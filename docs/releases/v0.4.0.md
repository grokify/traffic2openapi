# Release Notes: v0.4.0

**Release Date:** 2026-05-04

## Overview

Traffic2OpenAPI v0.4.0 migrates the omnistorage dependency from `github.com/grokify/omnistorage` to the new `github.com/plexusone/omnistorage` namespace. This release adopts the registry pattern for backend creation, providing a cleaner API and automatic backend registration.

## Highlights

- **Omnistorage Migration**: Migrate to plexusone/omnistorage with registry pattern support

## Breaking Changes

This release contains breaking changes for users who import `pkg/ir` and use the StorageProvider with omnistorage backends.

### Import Path Changes

**Before (v0.3.x):**

```go
import (
    "github.com/grokify/omnistorage"
    "github.com/grokify/omnistorage/backend/file"
    "github.com/grokify/omnistorage/backend/s3"
)

backend := file.New(file.Config{Root: "/data"})
```

**After (v0.4.0):**

```go
import (
    "github.com/plexusone/omnistorage"
)

// Use registry pattern - all backends auto-registered
backend, err := omnistorage.Open("file", map[string]string{"root": "/data"})
```

### Registry Pattern

The new omnistorage package uses a registry pattern where all backends are automatically registered via `init()` functions. This eliminates the need to import individual backend packages:

```go
// Create backends by name - no direct imports needed
backend, _ := omnistorage.Open("file", map[string]string{"root": "/data"})
backend, _ := omnistorage.Open("s3", map[string]string{"bucket": "my-bucket", "region": "us-east-1"})
backend, _ := omnistorage.Open("gcs", map[string]string{"bucket": "my-bucket"})
```

### Available Backends

| Backend | Registry Name | Description |
|---------|---------------|-------------|
| File | `file` | Local filesystem storage |
| Memory | `memory` | In-memory storage (testing) |
| Channel | `channel` | Go channel-based IPC |
| SFTP | `sftp` | SSH file transfer |
| Amazon S3 | `s3` | AWS S3 storage |
| Google Cloud Storage | `gcs` | GCS storage |
| Google Drive | `drive` | Google Drive storage |
| GitHub Releases | `github` | GitHub release assets |
| Dropbox | `dropbox` | Dropbox cloud storage |

## Changed

- Replace `github.com/grokify/omnistorage` with `github.com/plexusone/omnistorage` and `github.com/plexusone/omnistorage-core`
- Use `omnistorage.Open()` registry pattern for dynamic backend creation

## Dependencies

- Add `github.com/plexusone/omnistorage` v0.2.0 (replaces grokify/omnistorage)
- Add `github.com/plexusone/omnistorage-core` v0.4.0 for compress/gzip and format/ndjson utilities
- Update `github.com/pb33f/libopenapi` from v0.34.3 to v0.36.3
- Update `github.com/fsnotify/fsnotify` from v1.9.0 to v1.10.0

## Upgrade Guide

### Step 1: Update Imports

If you use the StorageProvider directly, update your imports:

```go
// Old
import "github.com/grokify/omnistorage/backend/file"

// New
import "github.com/plexusone/omnistorage"
```

### Step 2: Update Backend Creation

Replace direct backend constructors with the registry pattern:

```go
// Old
backend := file.New(file.Config{Root: "/data"})

// New
backend, err := omnistorage.Open("file", map[string]string{"root": "/data"})
if err != nil {
    return err
}
```

### Step 3: Run go mod tidy

```bash
go mod tidy
```
